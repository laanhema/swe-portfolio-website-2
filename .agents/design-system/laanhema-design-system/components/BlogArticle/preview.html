NgRx SignalStore patterns I keep reaching for.

Lauri Makkonen/Sep 18, 2026/8 min read

How Tralla's board state stayed small: feature stores, computed selectors and the one rule I'd break again.

Tralla started as a weekend Kanban clone and grew into the project where I finally stopped fighting state management. The board, its columns and every card live in BoardStore, and the components only ever read signals.

One store per feature

The rule: if two components need the same data, it goes in a store; if only one does, it stays local. Angular's signals guide covers the primitives; the store adds the structure.

  • Feature stores, not one global store
  • Computed selectors for anything derived
  • Methods for writes, never patchState from a component
export const BoardStore = signalStore(
  withState({ columns: [] as Column[] }),
  withComputed(({ columns }) => ({
    cardCount: computed(() => columns().reduce((n, c) => n + c.cards.length, 0)),
  })),
);
Derived state is a bug you haven't written yet. Compute it.

When I broke the rule

Drag-and-drop needed optimistic updates, so the column component owns a short-lived copy of its cards until the drop settles.
